## 反模式结论

**LLM 设计判断：中度明显的 AI 模板感。** 五个同构的“彩色顶边 + Emoji + 大数字”指标卡属于典型 hero-metric 模板；报告页是无差别卡片墙；Emoji 同时承担品牌、导航、动作、指标、文件类型和状态，视觉语言不稳定。大量 `.band`、卡片和嵌套小卡片代替了真正的信息编排。优点是没有玻璃拟态或夸张动画，基础后台组件仍然熟悉可用。

**确定性扫描：** 共 1 个 warning，位于 `src/conflux/workbench/static/app.css:427`，规则为 `layout-transition`。文件格式占比条通过 `transition: width 0.5s ease` 动画宽度，会触发布局计算。不是误报，但仅影响少量条形图，实际性能风险较低，可改为 `transform: scaleX()`。

**浏览器证据：** 页面、资源、中文编码和主要视图切换均正常。检测覆盖层未运行：浏览器页面作用域为只读，mutation preflight 失败，因此没有可靠的用户可见 overlay，也没有伪称已注入。

## 总体印象

这是一个功能骨架完整、视觉上干净的内部工具，但它更像“Python 工作流的控制面板”，还不是“研究者愿意每天使用的研究工作台”。最大机会不是换颜色，而是把页面从按模块分栏改为按研究任务、依赖状态和下一步行动组织。

## 做得好的地方

1. 侧栏顺序和“收件箱 → 评分 → 入库 → 索引 → 查询”提示建立了基本工作流心智模型。
2. 输入框、按钮、表格、空状态和反馈风格基本统一，学习成本不高。
3. 查询主流程克制，默认只展示问题与执行按钮，高级配置折叠的方向正确。

## 优先问题

### [P1] 仪表盘不是工作入口，只是资产计数页

**为什么重要：** 用户知道系统里有什么，却不知道配置是否完整、上次任务是否失败、现在最该做什么。

**怎么改：** 首屏改为研究工作流控制台，突出“继续上次研究 / 新建查询”、能力检查、进行中任务、最近结果和待处理异常；资产统计降为次要区。

**建议命令：** `/impeccable shape 工作台信息架构`

### [P1] 前置依赖和表单逻辑没有被界面管理

**为什么重要：** Embedding、搜索未配置时查询按钮仍可用；选择在线源仍显示 Fixture；两个同名输出目录同时出现，用户容易失败且不知道原因。

**怎么改：** 执行前展示能力检查；不可用动作禁用并解释原因；按数据源条件显示字段；合并重复目录；路径提供最近位置和合理默认值。

**建议命令：** `/impeccable harden 工作台执行流程`

### [P1] 报告浏览无法承载真实规模

**为什么重要：** 大量长路径被塞进同构卡片，扫描、比较和定位成本高；移动端退化为无限长的单列卡片。

**怎么改：** 使用高密度列表/表格，增加搜索、目录或来源分组、类型标签、日期范围与排序；采用列表 + 固定预览的左右分栏。

**建议命令：** `/impeccable layout 报告浏览`

### [P2] 缺少可信的异步状态与恢复机制

**为什么重要：** 查询阶段文字是定时轮播，可能误导；长任务不可取消；失败依赖短暂 toast 或原始 JSON。

**怎么改：** 接入后端真实阶段、耗时与日志；支持取消、重试、保留输入；把错误持久显示在操作区域并链接至具体配置项。

**建议命令：** `/impeccable harden 查询与入库状态`

### [P2] 视觉语言模板化，缺少研究工具气质

**为什么重要：** 彩色顶边指标卡、Emoji 和卡片墙削弱专业可信度，装饰与重要内容争抢注意力。

**怎么改：** 统一使用专业图标库与克制的语义色；减少卡片与嵌套；用列表、分栏、状态轨道和时间线表达研究流程；建立更紧凑的研究工具排版。

**建议命令：** `/impeccable polish 工作台视觉系统`

## 认知负荷

8 项检查失败 5 项，属中高负荷。主要失败在信息分块、视觉层级、最少选择、工作记忆与渐进披露：报告页一次呈现大量同构卡片；收件箱同屏约 9 个输入/决策点；仪表盘五个指标等权；依赖关系要求用户记忆；无关字段未随数据源隐藏。通过项是单页总体聚焦、内容有区域分组、查询高级选项使用折叠。

## 情绪旅程

首次进入时稳定但无明确下一步；看到“未配置”却不知影响时产生不确定；输入查询是体验高点；等待时因伪阶段、不可取消进入低谷；完成或失败后只有 toast 与原始输出，缺少摘要、下一步和恢复路径，结束体验偏弱。

## 角色红旗

**Alex（效率型专家）：** 无快捷键、命令面板、最近查询重跑或批量报告操作；报告只能逐个打开；长任务不能取消或显示可靠进度。

**Sam（无障碍依赖者）：** Emoji 增加读屏噪声；忙碌点依赖颜色和 `title`；toast 无 `aria-live`；当前导航无 `aria-current`；缺少 `:focus-visible` 与 `prefers-reduced-motion`。

**Jordan（首次使用者）：** Fixture、画像、Chroma、Embedding、RAG 等术语缺少关系解释；“未配置”不能直接修复；仪表盘没有推荐第一步；在线源与 Fixture 同时出现。

## 次要观察

- 窄屏导航换成两行顶部按钮，品牌、导航和内容争抢首屏空间。
- 超宽桌面表单字段过长；11px 标签和辅助文本偏多。
- 页面主标题始终是“本地研究工作台”，当前视图名称层级偏弱。
- Dashboard 源码存在未显示的重复“最近报告”区域，后续易维护分叉。
- 卡片 hover、toast 与忙碌动画没有 reduced-motion 替代。

## 值得追问的问题

- 用户打开工作台后的唯一首要任务，是继续研究、修复配置，还是查看最近结果？
- 报告是附属文件还是核心成果？若是核心成果，为何浏览体验仍像文件目录？
- 缺少搜索或 Embedding 时，系统应阻止查询，还是明确展示降级模式？
- 去掉 Emoji 和彩色顶边后，这个界面还剩多少 Conflux 自身的产品识别度？
