## 0. 一句话定位

在 P3 确定性证据管道之上，为研究生用户补齐"个性化（A）、多视角（B）、对话化（C）、实验与写作闭环（D/E）"四层能力，同步引入业界标准工程栈（FastAPI、可观测性、MCP、工程卫生），并坚持三条既有原则：**本地优先、证据先于结论、功能通用**。

## 1. 动机

| 动机 | 对应项 |
|---|---|
| 单模型训练偏好、世界知识差异、同一上下文思维僵化 | B 多模型评审团 |
| 跨会话个性化缺失（偏好/术语/纠正不沉淀） | A 用户记忆 |
| 使用门槛高（CLI/分页面操作），缺乏统一入口 | C 对话入口 |
| 实验—代码—报告之间的信息断裂 | D 实验追踪与周报 |
| 文献阅读到写作的断裂 | E 文献笔记与代码问答 |
| 工程成熟度与可展示性不足（"玩具感"） | C 平台 + 工程卫生横切 |

## 2. A–E 能力总览、优先级与取舍顺序

| 项 | 能力 | 优先级 | 实施批次 | 依赖 | 主要复用基建 | 分项文档 |
|---|---|---|---|---|---|---|
| A | 用户记忆 + 技能库 | **P0** | 第 1 批 | 无 | SQLite、EventStore 采集器、插件协议、config_store | [A_用户记忆与技能库.md](p4/A_用户记忆与技能库.md) |
| B | 多模型评审团 | **P0** | 第 1 批（与 A 并行） | 无 | verification/arbitration 节点、M5 评测 harness、深度分档 | [B_多模型评审团.md](p4/B_多模型评审团.md) |
| C | 对话入口 + 工程化平台 | **P0** | 第 3 批 | A、B 结论 | M3 Job/EventStore/ApprovalRequest、P3 v1 API、agent.py | [C_对话入口与工程化平台.md](p4/C_对话入口与工程化平台.md) |
| D | 实验追踪 + 导师周报 | P1 | 第 4 批 | A（周报个性化） | 周期审计、事件流、P3.4 链接层 | [D_实验追踪与导师周报.md](p4/D_实验追踪与导师周报.md) |
| E1 | 代码问答（AST 分块） | P1 | 第 5 批 | C（入口） | P3.4 项目文档索引与覆盖链路 | [E_文献笔记与代码问答.md](p4/E_文献笔记与代码问答.md) |
| E2 | 文献笔记与写作闭环 | P2 | 第 6 批 | C、D | P3.4 链接层、索引器、MCP | 同上 |

**取舍顺序理由**：

1. **A、B 先做**：零破坏（纯增量，不改研究管道）、可独立验收；A 是所有个性化的地基，B 的 A/B 结论决定 C 对话里 deep 档是否开评审团。
2. **C 是枢纽**：平台改造最大（FastAPI、流式、观测、MCP），一次性吃下"工程栈 + 展示"诉求；若先做 D/E 而入口未成，收益无法日常化。
3. **D 排在 C 后**：周报/实验登记的日常入口就是对话，复用 C 的门禁与流式。
4. **E1 先于 E2**：代码问答确定性收益高、依赖弱；E2 文献笔记依赖模型质量且最重，最后做。
5. **工程卫生横切项**（ruff/mypy/CI/Alembic/uv/Docker）不单独立项，随 C 落地。

## 3. 跨项设计约束（所有分项必须遵守）

1. **功能通用**：所有 schema/工具/技能不为 Conflux/FusionAgent 特制；fusionagent001 由用户自行补计划测试（延续 P3 约定）。
2. **证据先于结论**：A–E 全部产出可追溯；模型判断标注来源与确定性边界；对话形态同样逐条带证据链接。
3. **确定性优先**：路由、门禁、校验、引用审计保持确定性；LLM 只做生成与判断，永远不能推翻确定性裁决。
4. **预算硬约束**：沿用 quick/standard/deep 三档（55k/75k/320k）；所有新 LLM 触点纳入 `BudgetState` 预扣；默认档成本增量需离线验证后才默认化。
5. **本地优先**：记忆/观测/实验数据全部本地 SQLite/文件，不上传项目内容。
6. **安全**：记忆、笔记、外部工具输出均为可注入面——结构化存储 + `sanitize.py` 清洗 + 白名单校验。
7. **评测先行**：每个 LLM 新能力先离线 A/B 或闭环脚本（沿用 `scripts/p3x_closure.py` 模式）再默认化，报告落 `reports/evaluation/p4/`。

## 4. 决策记录修订清单（新 ADR，实施时写入 docs/adr/）

| 编号 | 内容 |
|---|---|
| ADR-01 | 多模型 ensemble 评审 ≠ 多智能体协商：修订 [研究查询重设计.md](研究查询重设计.md) §3.7 "不引入多智能体框架"的适用范围——确定性编排不变，纯模型判断点（verification/arbitration 等）允许预算受控的多模型评审团 |
| ADR-02 | 对话入口 = 路由 + 编排 + 呈现层，不重写研究管道；`answer_first` 保持唯一管道 |
| ADR-03 | FastAPI 作为 `/api/chat/*` v2 层载体引入（对话流式/校验/文档的实际需求），旧 stdlib 端点冻结共存 |
| ADR-04 | MCP 作为插件协议（M1）的对外互操作补充，不替代 |
| ADR-05 | 记忆注入边界：只注入偏好/术语/风格，事实性内容永远走 RAG 证据链 |
| ADR-06 | 工程卫生横切项与 C 捆绑落地，不单独立项 |

## 5. 明确不做清单

- **外部 CLI 唤起**（2026-08-13 已确认砍掉；以 MCP server 反向替代——让外部 agent 调用 Conflux 工具，而非 Conflux 唤起外部 CLI）。
- **LLM 框架迁移**（LangChain → 其他封装）：对用户零收益，风险巨大。
- **Redis / 微服务 / 多租户 / 远程 Worker**：M6 条件未触发，本地单用户场景引入反而说明不懂克制。
- **多用户协作 / 团队模式**：M6 范围。
- **语音 / 多模态输入**：无真实需求。
- **知识图谱 / Neo4j**：无真实需求证据。

## 6. 成本与预算总则

| 新 LLM 触点 | 成本增量（相对现状） | 控制手段 |
|---|---|---|
| B 评审团 | standard +1 call/判断点，deep +3 call/判断点 | 仅判断点开团；quick 强制关闭；成员 max_tokens 减半 |
| C 意图路由 | +1 小 call/轮（规则未命中时） | 规则优先；flash 模型；结果缓存 |
| C 受控 agentic 通道 | 按步预扣，≤3 步 | max_iterations、BudgetState、白名单工具 |
| D 周报 | +1-2 call/周 | 模板注入，模型仅组织语言 |
| E1 代码问答 | +0（纯检索 + 确定性图遍历） | — |
| E2 文献笔记 | +2-3 call/篇 | quick 档不开放；审计兜底 |
| A 记忆注入 | +0（系统前缀 ≤300 token） | 条数上限 5、kind 白名单 |

## 7. 分项验收总则

每项验收含四类：**质量**（离线评测/闭环脚本）、**成本**（预算不破）、**通用性**（非 Conflux 特制）、**回归**（既有 631 项测试 + 确定性裁决不回归）。全部证据落 `reports/evaluation/p4/`，状态回写 [执行计划v1.md](执行计划v1.md) 状态表。
