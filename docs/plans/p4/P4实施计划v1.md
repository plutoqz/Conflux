## 0. 顺序与理由

| 阶段 | 内容 | 为什么这个顺序 |
|---|---|---|
| 一 | **B 多模型评审团**（映射 P4.1） | 简历"多智能体协作"表述的支柱；A/B 报告本身就是面试材料 |
| 二 | **C 对话入口最小集**（映射 P4.2 的一部分） | 盘活技能栏"MCP/流式输出"两个词；FastAPI 工程栈落地 |
| 三 | **A 用户记忆与技能库**（映射 P4.0） | 最软的一环，面试被深挖概率最低，最后补 |

每阶段独立可验收、独立可投递；阶段内任务均可再拆。横切要求贯穿全程：**通用性**（不为 Conflux/FusionAgent 特制）、**每阶段全量回归**、**证据落 `reports/evaluation/p4/`**、**状态回写 [执行计划v1.md](../执行计划v1.md)**。

## 1. 阶段一：B 多模型评审团

### B1 配置层：`research.panel` 与 Profile 扩展

- 锚点：`config.yaml` `research:` 段；`src/conflux/research_modes.py:23-128`（`ResearchModeProfile`）、`:225-260`（`resolve_research_profile`）、`:288-340`（`validate_research_model_profiles`）
- 步骤：
  1. `config.yaml` 新增 `research.panel` 段（`enabled_by_depth: {quick: false, standard: true, deep: true}`、`roster.verification: [verifier, balanced]`、`roster.arbitration: [planner, flash]`、`referee: balanced`、`quorum: majority`）。
  2. `ResearchModeProfile` 增加 `panel_enabled: bool`、`panel_roster: dict[str, list[str]]`、`panel_referee: str` 字段；`resolve_research_profile` 解析。
  3. `validate_research_model_profiles` 增加 panel 校验：同一判断点成员必须来自不同 preset（防"同一模型多采样"伪多样性）。
- 测试：Profile 解析 + 异构 roster 校验拒绝同 preset 配置。
- 验收：quick 档强制 `panel_enabled=False`，配置不可打开。

### B2 模型层：panel 成员与裁判模型构建

- 锚点：`src/conflux/model_factory.py:510-605`（`create_research_models` 按角色构建 `BudgetedChatModel(BoundedChatModel(...))`）
- 步骤：
  1. `create_research_models` 扩展：为 `panel_roster` 中每个成员构建独立模型实例（复用 `create_chat_model`，成员 `max_tokens` 减半，下游预留按判断点阶段计算），裁判单独构建。
  2. 返回结构增加 `panel_models` 字典（`{judgment_point: [member_models], referee}`），quick 档为空。
- 测试：成员 max_tokens 减半断言；quick 档无 panel 模型。

### B3 协议与提示词：`PanelReview` 模块

- 锚点：`graph_v2.py:642-671`（`_invoke_json` 单次调用模式）、`:619-639`（`_budgeted_model_invoke` 预算预扣）；`src/conflux/research_prompts.py`（提示词常量区）
- 步骤：
  1. 新文件 `src/conflux/panel.py`：`PanelReview` dataclass（input_snapshot / members / referee / result）；`run_panel(members, snapshot, referee, budget_state)`：
     - 成员**并行**调用（复用 `_invoke_json` 模式，每成员一次 `model_calls` 预扣）；
     - 成员输入只含不可变快照，**互不可见彼此输出**；
     - 成员输出 JSON 契约 + verdict 白名单校验；
     - 分歧规则：全一致 → 原置信；多数 vs 少数 → 降一级 + 异议原文入 payload；均分 → `uncertain` 保留全员意见。
  2. `research_prompts.py` 新增 `PANEL_MEMBER_SYSTEM`（persona 插值：严格批判者/领域务实者/风险敏感者）与 `REFEREE_SYSTEM`。
- 测试：三态分歧规则、白名单拒绝、成员输出互不可见（构造断言）、预算耗尽降级。

### B4 挂载 verification（核心变更）

- 锚点：`graph_v2.py:954-998`（`_verification_payload`）、`:999-1085`（`verification_node`）、`:1048-1053`（确定性裁决优先断言）、`:3723-3826`（`create_v2_research_graph` 节点接线，`:3802` 传入 `verifier_model`）
- 步骤：
  1. `verification_node` 模型层替换：`panel_enabled` 时以 `run_panel` 替代单 verifier 调用；quick 档走原单模型路径（零回归）。
  2. 保持 `1048-1053` 约束：panel 任何成员/裁判的 `supports` 都不能推翻确定性 `insufficient/uncertain`——扩展为"panel 版本"断言。
  3. `verification_result` 增加 `panel: {members: [...], dissent: [...], referee: ...}` 字段进 JudgmentRecord payload（sidecar 可追溯）。
  4. 可选子任务：`arbitration_node`（`:770-855`）deep 档挂载 panel（第二判断点）。
- 测试：quick 档行为与旧版逐字节一致（回归）；deep 档产出 panel 字段；确定性优先断言覆盖 panel 路径。

### B5 预算：panel 预扣

- 锚点：`src/conflux/research_protocol.py:1083-1178`（`BudgetState`）、`graph_v2.py:605-618`（`_budget_state_for`）
- 步骤：`run_panel` 每次成员/裁判调用前 `reserve("model_calls")`（成员每人 1、裁判 1），耗尽 → 按既有 `_BudgetRejected` 模式降级为单模型或确定性兜底，记 `dropped_reasons`。
- 测试：压测 deep 档，panel 调用数不超 `model_calls` 上限。

### B6 单元/集成测试

- 新文件 `tests/test_p4_panel.py`：协议解析、分歧三态、异构校验、确定性优先回归、quick 关闭、预算硬上限（对照设计文档 B1–B5 验收表）。

### B7 A/B 评测（默认化的门）

- 锚点：`src/conflux/research_evaluation.py` / `evaluation_m5.py`（评测聚合）、冻结标注集（P2 75 篇 + KG 136 篇终审）
- 步骤：新脚本 `scripts/p4_panel_ab.py`——同证据快照下"单 verifier vs 评审团"对照；指标：误判率、待核验率、token 成本、并行后 P95 延迟。
- 报告：`reports/evaluation/p4/b_panel_ab_20260813.md`。
- **默认化条件**：误判率下降或持平 **且** 成本增量 ≤1.5× → 写入 `config.yaml` 默认；否则评审团保留为 deep 可选。

**阶段一里程碑 M1**：B7 报告产出 → 简历 v2 第 1 条（多模型评审团）可投。

## 2. 阶段二：C 对话入口最小集

### C1 FastAPI v2 骨架

- 锚点：`src/conflux/workbench/server.py:3183`（`WorkbenchHandler(BaseHTTPRequestHandler)`，do_GET `:3218`、do_POST `:3356`、P3 路由 `:3489/:3543`）
- 步骤：
  1. 新目录 `src/conflux/workbench/api_v2/`（`app.py` + `schemas.py`）；Pydantic v2 请求/响应模型。
  2. 路由 `/api/chat/*`；uvicorn 与现有 ThreadingHTTPServer 同进程共存（老端点冻结不动，新功能只进 v2 层）。
  3. OpenAPI 文档可访问（`/docs`）。
- 验收：老端点回归零变化；`/docs` 覆盖 `/api/chat/*`。

### C2 意图路由（确定性优先）

- 步骤：`api_v2/router.py`——规则表（命令词/关键词）→ 动作白名单 `{research_query, run_radar, project_audit, cycle_summary, memory_query}`；未命中 → LLM 分类兜底（flash、结构化输出、**非白名单即拒绝**）→ 澄清问题。
- 测试：非白名单意图一律转澄清（无幻觉执行）；分类输出 schema 校验。

### C3 编排接线（复用既有 Job/门禁）

- 锚点：`src/conflux/workbench/jobs.py:340`（`JobManager.submit` 及 claim/events）；M3 `ApprovalRequest`
- 步骤：动作 → 既有 job 提交（research_query / paper_radar 复用现有 kind）；写操作（入库/雷达/实验登记）先 `ApprovalRequest`；读取 → P3 `/api/v1/projects/*`。
- 测试：写操作未经确认零执行。

### C4 token 级流式

- 锚点：`jobs.py:45-72`（`_EventLog` cursor 模式）；当前 `graph.stream(stream_mode="values")` 流状态快照
- 步骤：LLM 逐 token 输出经 SSE 转发 + 任务进度事件复用 `JobManager.events` cursor 读取。
- 验收：对话响应 token 级可见；进度事件与 token 流不互相阻塞。

### C5 受控 agentic 通道（可选子任务，时间紧可降级）

- 锚点：`src/conflux/agent.py:85-151`（`ResearchAgent.bind_tools` + `execute_tools` + `max_iterations=3`）
- 步骤：白名单工具（`search_rag`/`search_web`/`project_state`）`bind_tools`，每步 `BudgetState` 预扣，产出进 Evidence Ledger；仅开放类任务经路由进入。

### C6 MCP server

- 步骤：新文件 `src/conflux/mcp_server.py`——stdio 暴露 3–5 个工具（`search_rag`/`search_web`/`paper_radar`/`project_audit`）；工具执行复用现有 tool 实现（`tools/rag.py`、`tools/web.py`）。
- 明确后置：MCP client、观测面板、OTel/Langfuse 导出（设计文档 §5-6 的完整版）。

### C7 工程卫生横切（随本阶段落地，可拆子任务并行）

| 子任务 | 内容 |
|---|---|
| C7a | ruff + mypy + pre-commit 接入 |
| C7b | CI 矩阵（3.11/3.12）+ coverage 门禁 |
| C7c | Alembic 接管 0001–0009 及后续 migration |
| C7d | uv + pyproject 完整化（发布流程） |
| C7e | Docker devcontainer + 单命令安装 |
| C7f | 观测最小版：structlog + LLM 调用记录（模型/角色/token/耗时/成本估算） |

### C8 测试与 demo

- `tests/test_p4_chat.py`（路由白名单兜底、门禁零执行、流式、OpenAPI 契约）。
- `scripts/p4_demo.py`：全 fixture + 确定性模型零成本剧本（种子论文 → 雷达 → 入库 → 查询 → 周报），无外部 API。

**阶段二里程碑 M2**：C1–C4、C6、C8 完成 → 简历 v2 第 3 条（对话入口 + MCP + 流式）可投。

## 3. 阶段三：A 用户记忆与技能库

### A1 存储层：`0009_user_memory`

- 锚点：`src/conflux/projects/repository.py`（migration 0007/0008 模式）
- 步骤：新 migration `0009_user_memory`（字段见 [A 设计 §2](A_用户记忆与技能库.md)）；`user_memory` repository（CRUD + supersedes 链 + pending 队列 + 容量上限 500）。

### A2 采集器：`memory_collector`

- 锚点：`src/conflux/projects/collectors.py`（确定性幂等 + dedup key 模式）
- 步骤：触发源四路——报告反馈/雷达决策覆写/周期审计 confirm（直接入 active）、对话纠正（入 pending）；全部带 `source_event_id` 回源；确认门 API `confirm|reject`。

### A3 注入（最小、安全、可追溯）

- 锚点：`graph_v2.py:539-586`（`status_bar` 前缀组装）
- 步骤：系统提示前缀注入——≤5 条、≤300 token、`kind` 白名单（偏好/术语/风格，fact 禁入）、注入前 `sanitize.py` 清洗；提示词明示"记忆是偏好参考，证据结论优先"。
- 测试：注入攻击记忆不改变证据裁决；前缀 token 上限断言。

### A4 技能库

- 锚点：`src/conflux/core/workflow_compiler.py`（YAML 工作流编译）、`core/registry.py`
- 步骤：`skills/*.yaml` 声明式技能（触发条件/步骤/工具白名单/门禁/输出契约）；接入 workflow_compiler；内置 3 个种子技能（读论文笔记、周报草稿、实验可复现性检查）。

### A5 API 与界面

- `GET/POST /api/v1/memory`、`POST /api/v1/memory/{id}/confirm|reject`、`GET/POST /api/v1/skills`；工作台设置页"记忆"分组（复用 P3 设置分组对话框）。

### A6 测试

- `tests/test_p4_memory.py`：召回排序、supersede 链、pending 确认门、注入安全、容量上限（对照设计文档 A1–A5 验收表）。

**阶段三里程碑 M3**：A6 通过 → 简历 v2 第 4 条（智能体记忆）可投。
