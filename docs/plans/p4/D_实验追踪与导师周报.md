## 0. 目标

1. **实验成为一等公民**：假设/参数/指标/提交/产物/声明关联全链路登记，解决"这个实验为什么做、结论是否成立、对应哪次提交"的断裂。
2. **证据化周报**：周期审计升级为导师周报草稿，逐条带证据链接，一键导出。

## 1. 现状与复用

| 已有基建 | 复用方式 |
|---|---|
| `progress_audit` 产物扫描（tests/experiments 目录） | 实验产物自动采集 |

## 2. 实验数据模型（通用 schema，不为 Conflux 特制）

`experiments` 表（SQLite migration `0010_experiments`），最小字段：

| 字段 | 说明 |
|---|---|
| `id` / `project_id` | 主键、所属项目 |
| `name` / `hypothesis` | 实验名、假设 |
| `params` / `metrics` | JSON，参数与指标 |
| `status` | `draft` / `running` / `done` / `failed` |
| `commit_hash` | 对应代码提交 |
| `artifacts` | 产物文件引用（复用 ArtifactStore） |
| `linked_claims` | 与报告声明的关联（复用链接层） |
| `created_at` / `updated_at` | 时间戳 |

采集三路：

1. **CLI 登记**：`python -m conflux experiment register --project X --hypothesis ... --params ...`（U1 模式：登记即建记录）。
2. **产物扫描约定**：`results*.json` 键约定（如 `{metrics: {...}, commit: ...}`），progress_audit 扫描时自动关联。
3. **对话登记**（C 之后）："帮我登记一个实验"走 ApprovalRequest。

## 3. 周报草稿生成

流程：**周期审计 diff + 实验记录 + 已确认上周期摘要 → 模板注入 → LLM 仅组织语言 → 确定性校验 → 用户确认 → 定稿导出**。

- LLM 的输入全部是确定性数据；**数字/结论/提交哈希由模板注入，模型不可编造**。
- 输出后确定性校验：报告内每个数字/哈希必须能回溯到 Ledger/实验表，否则整段退回。
- 逐条证据链接（"完成 X：见 commit abc、实验 E12"）。
- 用户确认后定稿（复用周期审计 confirm 机制）；导出 Markdown。
- 个性化：A 记忆注入风格偏好。

## 4. 验收（D1–D4）

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| D1 | 通用 schema | fusionagent001 可登记实验（由用户补计划测试） |
| D2 | 数字可追溯 | 周报内 100% 数字/哈希可回溯（校验器测试） |
| D3 | 全链路闭环 | 实验→提交→周期审计→周报，闭环脚本 `scripts/p4_d_closure.py` |
| D4 | 模型不可编造 | 故意缺失实验数据时，周报不得出现未登记数字（回归测试） |

## 5. 风险与取舍

| 风险 | 对策 |
|---|---|
| schema 过度设计 | 最小字段起步，扩展走 JSON 列 |
| 周报美化事实 | 模板注入 + 事后校验双重兜底 |
| 采集口径混乱 | 三路采集统一走 `experiment_register` 应用服务 |
| 不做 | 实验调度自动化（GPU 排队等）；MLflow 集成（本地 SQLite 已够，避免重依赖） |
