# RAG 生产链路修复记录（2026-08-09）

## 背景与问题

全链路诊断发现三项“已验证结论与生产实现”之间的落差，直接拖累研究查询的
RAG 命中：

1. 索引覆盖不全：`conflux_docs` 仅 97 条论文分块，`data/documents` 下
   ESRI/NIST/wiki/AI 治理等普通资料未入向量库。真实复核中“AI 治理”
   查询 RAG 为 `no_evidence`。
2. 检索参数未落地：R1 结论建议 hybrid `top_k=60` 候选池，生产
   `config.yaml` 仍是 `top_k=10 / final_k=5`，召回宽度被人为压低。
3. 重排默认路径与结论冲突：R1 消融显示 LLM judge rerank 全面负优化
   （12 组中 10 降 1 平 1 微升，LLM judge 每批 23-30 分钟），但生产仍默认
   创建 `SemanticReranker`，并把 `semantic_score>=0.45` 作为准入门槛，
   导致部分真实查询被整体误拒。

## 修复内容

### 1. 全量索引覆盖

新增 `scripts/rebuild_index_full.py`：

- 从 `paper_promotion_manifest.json` 加载 203 个论文 summary/fulltext chunks，
  保留原 `chunk_id`/`paper_section`/`citation_ref` 等元数据，不再二次切分；
- 加载 `data/documents` 根目录 67 个 `.md/.txt` 普通资料，整篇截断
  （`plain_doc_max_chars=8192`）索引，避免 wiki 长文档产生数万子块；
- 跳过 `papers/pdfs` 原始 PDF：论文文本已在 `papers/papers/*.md` 抽取。

重建结果：270 个向量（203 论文 chunks + 67 普通文档），耗时约 28s。

### 2. 检索参数对齐

`config.yaml`：`retrieval.top_k` 10 -> 60，`retrieval.final_k` 5 -> 10，
与 R1 的候选池宽度建议一致。

### 3. rerank 默认关闭

- `config.yaml`：新增 `research.semantic_rerank: false`；
- `graph_v2.py`：新增 `llm_rerank_enabled` 开关，仅在显式开启时才创建
  `SemanticReranker`，删除“reranker_model 存在即自动创建”的隐式路径；
- `__main__.py`：生产路径按配置传开关，replay 路径安全读取角色模型。

关闭后 RAG 工具回退到确定性评分准入（`score>=0.25`），不再因语义评审
给 0 分而整体误拒。

## 受控验证（同一真实查询，改前 vs 改后）

### AI 治理查询

“高影响公共决策中的生成式AI治理目前存在哪些主要制度与实施缺口？”

- 改前（2026-08-05 真实运行）：RAG `no_evidence`；
- 改后（2026-08-09）：RAG `success`，命中 `ai-regulation.txt`、
  `wiki--eu-ai-act.md` 等本地治理资料，确定性综合分 1.00。

### 材料查询

“材料发现中图神经网络与等变神经网络的证据、适用边界和计算取舍有何差异？”

- 改后仍为 `no_evidence`：本地知识库本身缺少材料领域文档，检索到的论文
  chunks 被确定性评分判为 off-topic。这是知识覆盖限制，不是 rerank 误拒；
  该场景继续依赖 Web 兜底，并应在本地库补充材料领域资料后再评估。

- 未做完整 LLM 生成级 A/B（成本高）；本次验证聚焦检索层与 RAG 工具层命中，
